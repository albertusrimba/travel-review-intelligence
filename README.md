# Travel Review Intelligence

**Hotel Review Sentiment Classification with Machine Learning and FastAPI**

Travel Review Intelligence is an end-to-end machine learning project that classifies hotel reviews into two sentiment categories: **POSITIVE** and **NEGATIVE**. It demonstrates a practical workflow covering data inspection, cleaning, exploratory data analysis (EDA), model comparison, evaluation, prediction, REST API development, and automated testing.

## Project Objectives

- Inspect and clean a real-world hotel review dataset.
- Explore sentiment distribution and review characteristics.
- Build a text classification baseline using TF-IDF and Logistic Regression.
- Compare unigram features with unigram-plus-bigram features.
- Evaluate model performance on held-out test data.
- Serve predictions through a REST API.
- Test prediction logic and API endpoints automatically.

## Dataset

This project uses the **17k Hotel Reviews Dataset** from Hugging Face.

- **Source:** [17k Hotel Reviews Dataset](https://huggingface.co/datasets/Aditya1010/17k-hotel-reviews-dataset)
- **File used:** `balanced_dataset.csv`
- **Columns used:** `review`, `label`
- **Target labels:** `POSITIVE`, `NEGATIVE`

Please refer to the dataset source for the current license and usage terms before redistributing the data. The dataset page indicated an Apache-2.0 license when it was reviewed for this project.

### Data Inspection and Cleaning

The original dataset contained 17,840 rows and no missing values in the inspected columns. Exact duplicate review rows were identified and removed before model development.

| Data quality measure | Result |

## Modeling Approach

### Text Representation

TF-IDF (Term Frequency–Inverse Document Frequency) converts review text into numerical features for the classifier.

Two feature configurations were compared:

- **Unigram:** individual words.
- **Unigram + bigram:** individual words and two-word combinations.

### Classifier

Logistic Regression was used as a practical baseline for binary text classification. The trained scikit-learn pipeline is saved as `models/sentiment_model.joblib`.

### Evaluation Strategy

The deduplicated dataset was split using stratified sampling into:

- 60% training data
- 20% validation data
- 20% test data

The feature configurations were compared on the validation set. The selected unigram model was retrained on the combined training and validation sets, then evaluated on the held-out test set. A fixed random seed (`42`) was used for reproducibility.

## Results

### Validation Comparison

| Feature configuration | Accuracy | Macro F1-score |
|---|---:|---:|
| Unigram | 83.92% | 83.83% |
| Unigram + bigram | 83.60% | 83.49% |

The unigram configuration performed better on the validation set and was selected for final evaluation.

### Final Test Performance

| Metric | Score |
|---|---:|
| Accuracy | 84.40% |
| Macro F1-score | 84.32% |

| Sentiment | Precision | Recall | F1-score |
|---|---:|---:|---:|
| NEGATIVE | 83.48% | 87.60% | 85.49% |
| POSITIVE | 85.54% | 80.87% | 83.14% |

The results provide a baseline for further improvement. The model makes incorrect predictions, and its performance may vary on reviews from different sources, languages, or writing styles.

The final confusion matrix is saved as `reports/figures/final_confusion_matrix.png`. Other analysis artifacts, including `reports/final_metrics.json` and `reports/misclassified_reviews.csv`, are also generated by the project scripts.

## Getting Started

### Prerequisites

- Python 3.12 or a compatible Python version
- pip

### 1. Create and Activate a Virtual Environment

From the project root, run these commands in Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install Dependencies

```powershell
pip install -r requirements.txt
```

The API and test commands also require FastAPI, Uvicorn, and HTTPX. If they are not already listed in `requirements.txt`, install them with:

```powershell
pip install fastapi "uvicorn[standard]" httpx
```

### 3. Prepare the Dataset and Model

Place `balanced_dataset.csv` at:

```text
data/raw/balanced_dataset.csv
```

The prediction API expects the trained model at:

```text
models/sentiment_model.joblib
```

If the model file is not included in a clone, run the project scripts in the appropriate order to recreate it. Ensure the dataset is available before running scripts that load it.

### 4. Run the API

From the project root:

```powershell
uvicorn src.api:app --reload
```

By default, the API runs at `http://127.0.0.1:8000`.

Interactive API documentation is available at:

- Swagger UI: `http://127.0.0.1:8000/docs`

Keep the server terminal running while making requests. Press `Ctrl+C` to stop the server.

## API Usage

### Health Check

**Endpoint:** `GET /health`

Example response:

```json
{
  "status": "healthy"
}
```

### Predict Review Sentiment

**Endpoint:** `POST /predict`

Example request:

```json
{
  "review": "The hotel was clean and the staff were very helpful."
}
```

The response contains a sentiment label and probability scores for the available classes. Example output for the review above:

```json
{
  "sentiment": "POSITIVE",
  "probabilities": {
    "NEGATIVE": 0.0342,
    "POSITIVE": 0.9658
  }
}
```

Probability values are model-generated scores and should not be interpreted as guarantees of correctness or as calibrated confidence unless calibration has been evaluated separately.

- API health check
- Positive and negative API predictions
- Rejection of an empty API review

## Limitations

- The model predicts only two sentiment classes: positive and negative.
- TF-IDF and Logistic Regression may struggle with sarcasm, mixed sentiment, subtle context, or unusual wording.
- Probability outputs have not been established as calibrated confidence scores.
- The API has been tested locally; production deployment, service monitoring, and cloud deployment have not yet been implemented.
- Performance on new data from different sources has not yet been established.
